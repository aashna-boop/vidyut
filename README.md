# Vidyut — grid-intelligence prototype (v2)

Curtailment prediction, fault/theft localization, and fault isolation + service restoration (FISR), run on **four real
distribution-grid models** with **years of real hourly data**, plus a **mock** SCADA/DERMS integration layer and a 3D viewer.

**Read this first — the honesty rules this repo follows**

1. Every table below is generated by `make_tables.py` from computed files in `results/`; nothing in them is typed in or
   rounded up. Figures quoted in the prose were checked by hand against those tables.
2. Where a model did not beat a baseline, it says so. Where a metric cannot be measured, it says so and gives no number.
3. "Real" means recorded/published data or a real physical calculation. "Assumed" means a modelling choice made here.
   The two tables in the next section separate them. **This is still a simulation, not field validation** (see "What this
   does *not* show").

## What's real, what's simulated, what's assumed

| Piece | Status |
|---|---|
| Grid topologies + impedances | **Real published models** bundled with `pandapower`: `mv_oberrhein` (179 buses, 2 substations), CIGRE MV benchmark (15 buses), Kerber Dorfnetz (116 buses) and Kerber Vorstadtnetz (294 buses), the last two being 10 kV / 0.4 kV German LV/MV networks. |
| Power flow | **Real physics.** Every hour is a Newton-Raphson AC power flow (`pandapower`). ~44k (German data) and ~50k (Indian-solar data) hours per topology. |
| Hourly solar, Germany | **Real recorded data.** OPSD hourly ENTSO-E `DE_solar_generation_actual` ÷ `DE_solar_capacity`, 2015-2019. **This replaces the old "spread the daily total over 24 h with a guessed curve" step** — there is no guessed intra-day curve left. |
| Hourly solar, India | **Real, but modelled irradiance.** NASA POWER hourly all-sky irradiance + 2 m temperature at 27.54°N 71.92°E (Bhadla solar-park area, Rajasthan), 2015-2020, converted to PV output with a simple formula (assumed PR 0.86, −0.4%/°C). It is satellite/reanalysis-derived, **not metered plant output**. Cross-check: NASA POWER irradiance vs PVGIS-ERA5 modelled PV output, hourly correlation 0.98 over 52,608 h. |
| Hourly demand | **Real German national load** (OPSD/ENTSO-E). Used as a *shape* (÷ its maximum) applied uniformly to every load in the grid. **It is not Indian demand** — see "Indian data" below. |
| PV capacity | **Assumed.** Each topology's PV is scaled so it sits at the *same stress level* as the original `mv_oberrhein` scenario (6.9% of PV energy curtailed on the reference day 2018-06-20). Ratios (PV nameplate ÷ total load): 1.78× / 0.34× / 3.34× / 7.46×. Kerber nets ship with no PV; rooftop PV is placed on a seeded random ~50% of load buses. |
| Per-device variation | **Assumed.** PV output ±8%, each load ±5% (uniform), so buses differ. |
| Curtailment | **Rule assumed, applied to real physics.** A PV unit is throttled ×0.85 (up to 6 rounds) when the power flow shows voltage > 1.05 pu at its bus or an adjacent line > 100% loaded. Curtailment *labels* therefore come from this rule — the models learn (and are tested on) this simulator, not real utility curtailment logs. |
| Fault / theft events | **Injected, no real incident data exists** (utilities don't publish it, in India or elsewhere). Modelled as an unexplained extra draw at a bus (0.5–2% of total load, Q = 0.3 P); the network response is real power flow. |
| Sensors for localization | **Assumed sensor suite:** noise σ = 0.0005 pu (voltage), 0.02° (angle), 0.5 A (line current). Angle/current sensing is *not* free: it is the reason accuracy improved (see Product 2). |
| Sectionalising switches | **Real for `mv_oberrhein`** (its own 322 switches, 6 normally-open ties). **Assumed for CIGRE MV and both Kerber nets**, which ship no sectionalisers (CIGRE has only its 3 tie switches, Kerber has none): a sectionaliser is assumed on every other line. |
| SCADA / DERMS | **Mock.** No utility system is connected. See its section. |

## How the models are evaluated (so the numbers mean something)

* **Chronological split, no leakage:** train 2015-2017, validation 2018 (model/threshold selection), **test 2019 — never
  touched during training**.
* Everything below is retrained/rebuilt **per topology**. "Generalization across topologies" here means *the same method
  and data pipeline work on each grid*; it does **not** mean one trained model was transferred between grids (that wasn't
  tested).
* Rows are hourly pairs inside a real day; the 23:00→00:00 boundary (night) is never used.

## Product 2 — fault/theft localization

Method: fingerprint matching. One real AC power-flow probe per bus gives that bus's signature (how voltage, voltage angle
and line currents change everywhere); a live anomaly is matched to the closest fingerprint (cosine similarity). Trials use
**random real 2019 operating states** with per-device variation the dictionary doesn't know, plus sensor noise.

**What improved the number, and what didn't (all of it is in this table):**

* The original method (voltage only) gets 6–65% exact-bus depending on the grid — worse on big radial LV feeders.
  Adding **voltage-angle and line-current** measurements lifts it to 92–99%. This is a *sensor-suite assumption*, not
  free accuracy: if only 30% of buses/lines are instrumented it falls to 35–59% exact (but ≤5 hops stays 89–100%).
* **A mistake found and fixed along the way (reported, not hidden):** a first version built fingerprints for coarse
  operating-state bins. On PV-heavy grids that was measurably wrong — exact-bus accuracy fell from 98% when the dictionary's
  solar level matched to ~41% when it was off by 0.1. The fix is to build the dictionary **at the actual pre-fault state**
  (aggregate PV and load level, which SCADA/a state estimator would know). That requires an accurate network model and
  state estimate; per-device variation and noise remain unmodelled.
* Uncertainty: n = 300 trials (30 operating states × 10 faults). One standard error is roughly ±1.4 pp at 94% and
  ±2.8 pp at 60% if trials were independent; they are correlated within a state, so the true uncertainty is larger. No
  confidence intervals were computed.
* The old README's 10% figure is not directly comparable (different trial setup); the like-for-like reproduction of the old
  voltage-only method is the "voltage only" row.

## Product 3 — predictive maintenance: **no accuracy number exists, and none is given**

There is no public dataset of real grid-equipment failures (anywhere, for any country) to validate a failure predictor
against, so no metric can validly be assigned. What is provided is a physics-based **stress ranking only**: cumulative
(loading%)² per line — an I²R heating proxy — over all simulated days (`results/predictive_maintenance_<topology>.csv`,
shown in the viewer). The old "days to attention" extrapolation was **removed**: it wasn't grounded in data. The
transformer Montsinger's-rule aging estimate from the old script has also not been carried into this version.

## Fault injection + FISR (self-healing)

In the 3D viewer (**Fault Injection + FISR** tab) click any bus to inject a fault and watch the sequence:

1. **Fault + trip** — the feeder-head breaker (first line out of the substation on the path to the fault) opens; the whole
   downstream radial feeder loses supply.
2. **Localization** — Vidyut's fingerprint model ranks candidate buses from the noisy signature.
3. **Isolation** — only the faulted zone is cut out by opening its sectionalising switches. If the localizer was wrong the
   fault is still live: reclose → trips again → revert → next-ranked candidate (max 3 attempts, mimicking reclose-lockout
   practice). A fault counts as isolated only if the true fault bus is in the opened zone **and** cut off from the substation
   (otherwise a tie switch would re-energise the fault).
4. **Upstream restoration** — the feeder-head breaker recloses; the substation side is re-energised.
5. **Tie restoration** — buses stranded downstream are re-supplied by closing **real normally-open tie switches**. Each
   candidate tie is checked by AC power flow; the one with no voltage (0.95–1.05 pu) / loading (≤100%) violation and the most
   restored load wins.

Every stage is a real AC power flow on the real switch state (`fisr.py`). Sweep: **every feeder bus faulted once** at the
real **peak-load hour of 2019** (worst case for restoration headroom), with Vidyut's localization, and a control run with
*perfect* localization so switching logic and localization error are reported separately.

#### FISR — every feeder bus faulted once at the 2019 peak-load hour

| Topology | Faults | Localized exactly | Isolated ≤3 attempts | Lockout | Avoidable load restored (Vidyut) | (perfect localization) | Events needing ties → fully restored | Violations after − before (mean) |
|---|---|---|---|---|---|---|---|---|
| mv_oberrhein | 175 | 88.0% | 94.3% | 5.7% | 93.5% | 99.2% | 123 / 153 | 0 |
| CIGRE MV | 12 | 100.0% | 100.0% | 0.0% | 100.0% | 100.0% | 9 / 9 | 1.92 |
| Kerber Dorfnetz | 114 | 98.2% | 99.1% | 0.9% | 71.4% | 72.3% | 0 / 57 | 0 |
| Kerber Vorstadtnetz | 292 | 82.5% | 98.6% | 1.4% | 71.9% | 73.3% | 0 / 146 | 0 |

**Read honestly:**

* "Avoidable" load = load that lost power but is *not* in the isolated zone (the zone's own customers are unavoidably lost).
* **Ties decide restoration.** The two Kerber nets have **no tie switches**, so downstream customers cannot be restored
  (0 of 57 / 0 of 146 events needing ties): restoration tops out at ~72–73% *even with perfect localization*. Isolation and
  upstream restoration still work. This is a property of radial LV networks, not a bug.
* On `mv_oberrhein`, 30 of 153 tie-needing events were not fully restored. All 30 isolated the fault correctly first time:
  12 had no tie switch in reach and 18 closed one tie but left some load stranded (greedy single-tie choice, no load transfer
  or shedding). Even with perfect localization those events restore 95.5% on average (mean residual 0.8 MW, max 3.6 MW of
  60.9 MW).
* Localization errors cost real load: `mv_oberrhein` restores 93.5% with Vidyut's localization vs 99.2% with a perfect one
  (5.7% of faults end in lockout, i.e. not isolated in 3 attempts). On the Kerber Vorstadtnetz only 82.5% are localized exactly
  but 98.6% are isolated within 3 attempts, because misses are mostly neighbouring buses caught by the next candidates.
* CIGRE MV closes ties at a cost: its pre-fault state has **0** limit violations, but after restoration it ends with 0–10
  (mean +1.92): the tie search prefers a violation-free option, yet still closes the least-bad tie when none exists (a real
  system might shed load instead; that isn't modelled). CIGRE has only 15 buses, so 12 faults — a very small sample.
  `mv_oberrhein` and both Kerber nets add 0 violations on average.
* Faults at substation/HV buses (8 across the four grids) are excluded: no feeder head lies on their path, so distribution FISR
  doesn't apply.
* Not modelled: protection coordination and timing, load shedding, DER anti-islanding transients, multi-fault events. The 3D
  viewer **replays precomputed results** (the real model and switching engine were run for every bus and embedded); it does
  not solve power flow in the browser.

## Do the results generalize across topologies?

Same pipeline, four different grids (MV meshed-capable 179 bus, MV benchmark 15 bus, two radial LV feeders of 116 and 294 buses):

* **Product 1 holds up everywhere** — beats the mean baseline and persistence-RMSE on all 8 topology × dataset runs, with
  network-total correlation 0.97–0.99 and next-hour event F1 0.95–0.97, versus persistence 0.81–0.84.
* **Product 2 holds up only with the richer sensor suite.** Voltage-only accuracy varies hugely by grid (6% → 65% exact);
  the angle + current suite is consistent (92–99% exact) but depends on the sensing assumption, degrades sharply with
  sparse instrumentation, and needs a state-matched dictionary.
* **FISR depends on grid structure, not the ML.** Where real ties exist (oberrhein, CIGRE) restoration is 93.5–100%; on radial
  grids it cannot exceed ~73%.
* Limits: models are retrained per grid (no cross-grid transfer tested); all grids are German benchmarks, none is an Indian
  feeder; PV level is calibrated per grid to equal stress, which itself is an assumption; CIGRE's small size limits what
  can be concluded from it.

## SCADA / DERMS integration layer — **a mock, not a real integration**

`scada_mock.py` is an in-process message layer shaped the way a utility SCADA/DERMS would be. **No real utility system is
connected**; none was available.

* **Standard chosen: IEC 61850 object naming** (`LogicalDevice/LogicalNode.DataObject.DataAttribute`), e.g.
  `oberrhein_SW034/XSWI1.Pos.stVal`, `oberrhein_BUS057/MMXU1.PhV.phsA.cVal.mag.f`,
  `oberrhein_BUS057/VDYCRT1.NxtHrCrtlMW.mag.f`. Why: it is a *semantic* model (tags say what a thing is), which suits
  Vidyut's predictions/events that have no natural DNP3 point, and it is a widely used substation/DER integration standard.
  Which standard a *specific* utility requires must be confirmed with them.
* `dnp3_point_map()` emits the same tags as a **DNP3-style point table** (binary inputs, analog inputs, CROB controls,
  analog-output setpoints, with indexes) — the view a protocol gateway to legacy RTUs would use.
* What works: a point database (value / quality / timestamp / origin), SCADA publishing switch positions and measurements
  from a real power flow, Vidyut **reading** that state, **publishing** localization and curtailment-forecast tags, **issuing
  FISR switching commands** through select-before-operate (an unselected operate is rejected), SCADA republishing the new
  state, DERMS-side curtailment setpoints, and a read-only HTTP view (`/points`, `/point`, `/dnp3map`).
* What is **not** real: no MMS/GOOSE/DNP3 wire protocol, no IEC 62351 security, no RTU. The exact object/attribute names
  follow 61850 *conventions*; they must be checked against a utility's SCL/ICD files. Vidyut's own logical nodes (`VDY*`) are
  a private namespace.
* Tested (`test_end_to_end.py`, passes on `cigre_mv` and `mv_oberrhein`): after Vidyut's plan is executed through the SCADA
  mock, the resulting state's load served and de-energised-bus set equal the FISR engine's own power-flow result (e.g.
  60.2525 MW vs 60.2525 MW for a 2-tie restoration on `mv_oberrhein`).

Everything is checkpointed (`checkpoints/` = per-30-day simulation chunks, `results/` = per-topology outputs) and skips
finished work, so an interrupted run resumes. On a 20-core Windows machine the simulation took ~25 min per dataset;
Product 1 ~5–15 min per topology-dataset (with several running in parallel); localization + FISR a few minutes per topology. Then open
`vidyut_3d_visualization.html` in a browser (it loads Three.js from a CDN, so it needs internet). For a quick local check:
`python -m http.server` in this folder, then open `/website/index.html` (the marketing/demo site) or `/vidyut_3d_visualization.html` (the 3D lab).

## What this does *not* show

* No field data: labels and faults come from a simulator; localization/FISR were never run against a real feeder.
* Nothing is Indian-grid-specific: German benchmark grids; German demand; Indian solar only in the exploratory variant.
* The SCADA layer is a shape-compatible mock; integration with a real system would need protocol stacks, security, and
  SCL-based tag mapping.
* Predictive maintenance is a ranking with **no validated accuracy**.
